# 검증

## 환경과 명령

Java 21 / MySQL 8.4 / Node, 테스트 전용 빈 DB 사용. [루트 README](../README.md)의 compose.test.yaml 준비 후 실행.

```text
backend: .\gradlew.bat test bootJar --no-daemon
frontend/web: npm ci && npm run build
```

## 통합 테스트

- WorkflowIntegrationTest: 계약·상태·사진·손상·검수·인증·권한·동시성 20개.
- MigrationUpgradeTest: V10 자료가 있는 DB에 V11 적용 1개.
- 총 21개, 실제 MySQL에서 실행. H2 대체 DB 사용하지 않음.
- Hibernate validate 및 Flyway 신규 적용·업그레이드 포함.

| 대상 | 검증 내용 |
| --- | --- |
| 대여 | 신청→인수 기록 확정→이용→반납→검수, 취소 후 재신청 |
| 상태 기록 | 사진 없는 확정 차단, 최신 미확정 기록으로 이용 시작 차단 |
| 차수 | 기존 확정 기록의 변경 차단, 새 사진·관찰·증거 ID 복사, 원본 관찰 보존 |
| 검수 | 같은 계약·정확한 단계·확정 여부 검사, 기준 기록 고정, 추가 차수 차단 |
| 판정 | 기존 손상의 인수 참조 검사, 미판정·보류 완료 차단, 결과에 따른 가용/수리 전환 |
| 사진 | 해시 저장, 유효하지 않은 이미지 차단, 다른 기록의 사진 연결 차단 |
| 분석 후보 | 실행/순번 중복, 영역 범위, 판정과 독립된 저장 |
| 인증·권한 | 비밀번호 해시, 일반회원 고정 가입, 로그인, 다른 회원의 계약·사진 차단 |
| JWT | 구버전 회원 ID 공간의 토큰 거부, 올바른 issuer 토큰 허용 |
| HTTP | 400·401·403·409 구분, 인증 사진 원본 응답 |
| 동시성 | 동일 상품 신청 중 한 건만 성공, 동일 확정 기록의 다음 차수 생성 중 한 건만 성공 |
| DB 제약 | 부분적으로만 입력된 영역 좌표 거부 |
| 업그레이드 | 기존 계약·상태·사진·비밀번호 해시와 FK 연결 보존, 새 계약 테이블과 분리 |

실제 운영 데이터 이전·이미지 모델 추론 품질·성능 개선율은 이 테스트의 검증 대상이 아니다.

## 브라우저 확인

별도 빈 UI DB와 Chrome에서 다음 흐름을 실행했다.

- 고객 로그인 → 상품 신청 → 인수 사진 → 기록 확정 → 2차 기록 복사·확정 → 이용 시작 → 반납 → 반납 사진·기록 확정.
- 관리자 로그인 → 계약 조회 → 인수 2차·반납 1차를 검수 기준으로 선택 → 검수 시작·완료 → 신규 손상 없음 확인.
- 1440×1000, 390×844에서 화면 확인. 브라우저 실행 오류와 가로 넘침 없음.
- 브라우저에서 사용한 회원·상품·사진은 검증용 fixture. 실제 운영 실적으로 기재하지 않음.
