# PLAN — SCR-KSK-MAIN-001 (DEFAULT / RENT_DISABLED_NO_STOCK)

> 대상 Phase: PHASE.md "Phase 1 (SCR-KSK-COMMON)" 중 "메인 화면 UI" 부분
> 근거 문서: docs/09-screen-flow.md §2, §3.1 / docs/PROJECT_GUIDE.md §5.4, §14.1
> 범위: SCR-KSK-MAIN-001의 3개 Variant 중 **DEFAULT, RENT_DISABLED_NO_STOCK 2개만** 구현
> 제외 근거: `RETURN_DISABLED_WIREFRAME_ONLY`는 09번 문서 §7 `WF-CHANGE-009`에서 "제거 권장" 판정을 받은 Variant이므로 이번 구현 대상에서 뺀다.

## 1. 구현 목표

- 유휴 상태의 키오스크 첫 화면에서 대여소 재고를 조회해 **대여/반납 버튼을 표시**한다.
- 대여 가능 슬롯이 있으면 `DEFAULT`(두 버튼 모두 활성), 0개면 `RENT_DISABLED_NO_STOCK`(대여만 비활성 + 사유 배지)로 분기한다.
- 이 화면은 "모드 선택 UI"까지만 담당한다. 버튼 클릭 이후 이어지는 세션 생성·얼굴 인증 화면(`SCR-KSK-AUTH-001`)은 Phase 2/3 영역이므로 이번 범위에 포함하지 않는다(09번 문서 §3.1 종료조건: "모드 선택"까지).
- PHASE.md Phase 1에 함께 나열된 Loading/Error/Success 공통 화면, Face Guide Overlay는 **이 PLAN의 대상이 아니다** — Screen ID 단위 1 commit 원칙(CLAUDE.md Git Rules)에 따라 별도 PLAN/커밋으로 다룬다. 이번 화면에 필요한 최소한의 로딩 표시만 인라인으로 포함한다.

## 4. 상태 관리 방식 (Zustand)

`src/store/kioskMainStore.ts` 하나로 관리한다.

```
interface KioskMainState {
  status: 'idle' | 'loading' | 'success' | 'error'
  usableSlotCount: number | null
  observedAt: string | null   // ISO 8601, 서버 값 그대로 사용(클라이언트 재계산 금지)
  stale: boolean
  fetchStationSummary: () => Promise<void>
}
```

- `MainScreen`은 마운트 시 `fetchStationSummary()`를 1회 호출한다.
- Variant 판정은 컴포넌트 쪽에서 **파생값**으로 계산하고 스토어에는 별도 `variant` 필드를 두지 않는다(단일 소스 유지):
  - `status === 'loading' | 'idle'` → 조회 중 표시
  - `status === 'error'` 또는 `stale === true` → 09번 문서 §3.1 "Partial Success: 재고 수량을 알 수 없으면 대여만 보수 차단" 근거로 `RENT_DISABLED_NO_STOCK`과 동일하게 취급
  - `usableSlotCount === 0` → `RENT_DISABLED_NO_STOCK`
  - 그 외 → `DEFAULT`
- 자동 폴링/구독은 넣지 않는다(7절 리스크 참고, `DEC-SF-015` 미정).
- 얼굴/사용자 표시 정보는 이 화면에서 다루지 않으므로 CLAUDE.md의 세션 초기화 규칙과 충돌하는 상태는 없다.

## 5. Mock 데이터 구조

`src/api/stationApi.ts`:

```
export interface StationSummaryResponse {
  usableSlotCount: number
  observedAt: string   // ISO 8601
  stale: boolean
}

type MockScenario = 'DEFAULT' | 'RENT_DISABLED_NO_STOCK' | 'STALE'

// 수동 테스트 시 이 값만 바꿔서 확인한다 (6절 테스트 방법 참고)
const MOCK_SCENARIO: MockScenario = 'DEFAULT'

export async function fetchStationSummary(): Promise<StationSummaryResponse>
```

- 필드는 09번 문서 §3.1(재고 수량, `observedAt`·`stale` 처리 필요) + PROJECT_GUIDE.md §5.4(`KSK-STATION-001` 응답에 `observedAt`, `stale` 포함)에서 **문서로 확인된 것만** 사용한다.
- `usableSlotCount`라는 정확한 필드명, 대여소 전체 슬롯 수, 대여소 온라인 여부 등은 12번 문서(통합 API 명세) 원문을 아직 확인하지 못해 **확정이 아니다** — 이 이름은 잠정이며 실제 연동 단계에서 Backend 확인 후 바뀔 수 있음을 리스크에도 기재한다.
- `STALE` 시나리오는 `stale: true`를 반환해 "재고를 알 수 없어 보수적으로 차단"하는 경로를 수동으로 확인하기 위한 것.

## 6. 테스트 방법 (수동 확인 기준)

1. `npm run dev` 실행 후 브라우저로 접속.
2. `stationApi.ts`의 `MOCK_SCENARIO = 'DEFAULT'` 상태에서: 대여/반납 버튼이 모두 `#FFD700` 활성 스타일로 보이고 재고 수량 텍스트가 표시되는지 확인.
3. `MOCK_SCENARIO = 'RENT_DISABLED_NO_STOCK'`으로 바꾸고 새로고침: 대여 버튼이 `#D9D9D9` 비활성 스타일로 바뀌고, 배경 `#FFD8D3`의 "우산 재고 없음" 안내 배지가 노출되며, 반납 버튼은 계속 활성 상태인지 확인(09번 문서 §3.1 Variant 표: "대여 비활성, 반납은 유지").
4. `MOCK_SCENARIO = 'STALE'`로 바꾸고 새로고침: 대여 버튼이 "확인 중" 류 문구와 함께 보수적으로 막히는지 확인.
5. 화면 폭을 줄여(키오스크 터치스크린 가로 비율 가정) 버튼 크기·글자 크기가 터치에 충분히 큰지 육안 확인(PROJECT_GUIDE.md §8 체크리스트 12항 접근성).
6. `npm run build`로 타입 에러 없이 빌드되는지 확인.
7. `npm run lint` 통과 확인.

각 시나리오 확인 후 `MOCK_SCENARIO`를 원래 값(`'DEFAULT'`)으로 되돌려 커밋한다.

## 7. 예상 리스크

1. **API 통신 경계 문서 충돌**: 09번 문서(§1, §3.1)는 "Kiosk FE → Pi Local API"를 전제로 하지만, PROJECT_GUIDE.md v2.0(§3, `DEC-024 RESOLVED`)은 "Kiosk FE → Spring Kiosk API(`/api/v1/kiosk`) 7개만 사용, Pi는 보이지 않음"으로 아키텍처가 바뀌었다고 명시한다. PROJECT_GUIDE.md 문서 우선순위 규칙(§4: 12→10→09→11)에 따라 이번 Mock은 v2.0(`KSK-STATION-001`, Spring 직접 호출) 기준으로 설계한다. 09번 문서의 `CAND-KSK-LOCAL-AVAILABILITY-001`(Kiosk→Pi)은 구버전 계약으로 참고만 한다.
2. **`KSK-STATION-001` 응답 스키마 원문 미확인**: 12번 문서(통합 API 명세) 원문을 아직 읽지 않아 필드명·타입이 확정이 아니다. Mock 필드명은 잠정치.
3. **`stale` 판정 임계값 불명**: "오래된 값"이 몇 초/분 기준인지 문서에 없음. 클라이언트가 임의로 계산하지 않고 서버가 내려주는 `stale` boolean을 그대로 신뢰한다(PROJECT_GUIDE.md §5.3의 "서버 산정값만 표시, 클라이언트 재계산 금지" 원칙과 동일하게 적용).
4. **라우팅 방식 미정**: react-router 등 미설치, 새 라이브러리 도입은 사전 승인 필요(CLAUDE.md). 이번 화면은 버튼 클릭 후 화면 전환을 구현하지 않으므로 당장 문제는 없으나, Phase 2 착수 시 반드시 결정해야 한다.
5. **실시간 갱신 방식 미정(`DEC-SF-015`)**: Polling/SSE/WebSocket 선택이 아직 없어 "새로고침"(`ACT-KSK-MAIN-003`)은 이번엔 최초 1회 조회로만 구현. 이후 방식이 확정되면 재작업이 필요할 수 있다.
6. **색상 신뢰도**: PROJECT_GUIDE.md §14.1에 따르면 에러 텍스트 색(`~#C34E4B`)은 표본이 적은 근사치로, 단일 확정값이 아니다. 재고없음 배지 텍스트에 이 근사값을 그대로 쓴다.
7. **Tailwind v4 `@theme` 토큰 최초 도입**: 이번 파일에서 정의하는 토큰 네이밍이 이후 Phase(대여/반납/관리자 화면)의 사실상 기준이 된다. 이후 화면에서 팀 합의 없이 임의로 새 토큰을 추가하지 않도록 주의가 필요.
