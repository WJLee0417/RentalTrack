## 1. 구현 목표

- 홈 화면(`SCR-APP-HOME-001`)에 `HOME-001` 응답을 반영한 실제 UI를 구현한다(현재는 자리표시자 텍스트만 있음).
- 표시 항목: 사용자 정보, 현재 대여 요약, 미정산 요약, 알림 개수, 날씨 자리(placeholder), 중앙 영역(현재 상태 카드 + 지도 이동 링크).
- 부분 성공 원칙: 날씨는 처음부터 API 호출을 안 하므로 실패할 수 없다 — 대여·정산 조회 실패와 무관하게 항상 표시됨.
- Pull-to-Refresh(`INT-APP-004`)로 기존 `HOME-001` GET을 재호출한다(새 API 없음).

## 3. 각 요소의 역할과 결정 사항

### `home.ts` / `rental.ts`
PROJECT_GUIDE.md §5.4 원문 그대로:
```ts
interface HomeSummary {
  user: { displayName: string; schoolName: string }
  currentRental: CurrentRentalSummary | null
  pendingSettlement: { count: number; totalAmount: number }
  alertCount: number
}

interface CurrentRentalSummary {
  rentalId: string
  status: RentalStatus
  checkoutStationName: string
  rentedAt: string
  dueAt: string
  overdue: boolean       // 서버 계산값, 클라이언트 재계산 금지
  remainingFreeSeconds: number
}
```

### `homeApi.ts` (Mock)
`authApi.ts`와 동일하게 `MOCK_SCENARIO`로 시나리오 전환 가능하게 만든다(예: `WITH_ACTIVE_RENTAL` / `NO_RENTAL` / `OVERDUE_UNSETTLED`) — 수동 확인 시나리오 전환 목적.

### `HomeScreen`
- `useQuery(['home'], getHomeSummary)` (TanStack Query)
- 로딩: `LoadingScreen`
- 에러: `ErrorBanner` + 재시도 버튼(날씨는 애초에 API가 없어 이 에러 범위에 안 걸림 — 부분 성공 원칙 자연 충족)
- 사용자 정보: `user.displayName` + `user.schoolName`
- 현재 대여 요약 카드:
  - `currentRental === null` → "대여 중인 우산이 없어요" 안내
  - 존재 시 → 대여소명·기한(`dueAt`)·상태 Chip(§9.2 규칙: `ACTIVE|RETURNING` → "대여중", `overdue===true` → "연체중"으로 대체 표시. 새 Enum 생성 없이 기존 `status`+`overdue` 조합만 사용)
- 미정산 요약 카드: `pendingSettlement.count > 0`일 때만 노출, `totalAmount`는 서버 값 그대로 표시(클라이언트 재계산 금지)
- 알림: 아이콘 + `alertCount` 배지 숫자만 표시. `SCR-APP-NOTIFICATION-001`은 Phase 8 미착수 화면이라 탭해도 이동 없음(no-op) — 챗봇 버튼과 같은 이유로 자리만 배치
- 날씨 카드: 정적 "날씨 준비 중" 카드(아이콘/텍스트만, API 연동 없음)
- 중앙 영역(GAP-004 "현재 상태·지도 조합"): 위 현재 대여 요약 카드를 이 영역에 배치 + 그 아래 "지도에서 보기" 버튼 → `navigation.navigate('Map')`으로 지도 탭 전환(지도 자체는 그리지 않음)
- 챗봇 플로팅 버튼: 화면 우하단 고정 버튼, `onPress`는 아무 것도 안 함(주석으로 Phase 4 연결 예정 명시)
- Pull-to-Refresh: `ScrollView`의 `RefreshControl`에서 `refetch()` 호출

### `TabNavigator.tsx`
`Tab.Navigator`에 `TabParamList` 제네릭만 추가(화면 구성·탭 목록 자체는 변경 없음):
```ts
export type TabParamList = {
  Home: undefined
  Map: undefined
  History: undefined
  MyPage: undefined
}
```

## 4. 테스트 방법 (수동 확인 기준)

1. 로그인 후 홈 탭 진입 시 로딩 → 사용자 정보·대여 요약·미정산 요약·알림 개수·날씨 placeholder가 보이는지 확인
2. `homeApi.ts`의 `MOCK_SCENARIO`를 바꿔가며 "대여 없음" / "대여중" / "연체중+미정산" 케이스 화면 확인
3. "지도에서 보기" 버튼 클릭 → 지도 탭으로 전환되는지 확인
4. 챗봇 플로팅 버튼 클릭 → 아무 동작 없음(에러 없이 무시되는지만 확인)
5. 아래로 당겨서 새로고침 → 스피너 후 동일 GET 재호출되는지 확인
6. `npx tsc --noEmit` 통과 확인

## 5. 예상 리스크

1. **알림 배지 탭 무동작** — 사용자가 오해하지 않도록 배지 근처에 별도 안내 문구는 넣지 않고, 조용히 no-op으로만 둔다(알림 화면 자체가 Phase 8 범위라 억지로 임시 화면을 만들지 않음).
2. **`RentalStatus` 값 확장 필요성** — 이후 History/MyPage Phase에서 추가 조합이 필요해지면 `src/types/rental.ts`를 그때 확장한다(지금은 Home에 필요한 범위만).
3. **탭 간 네비게이션 타입** — `TabParamList` 제네릭 추가가 기존 `Tab.Screen` 등록에 영향 없는지 `tsc`로 확인 필요.

## 7. 추가 변경 (2026-08-04, 사용자 목업 스크린샷 확인 후)

사용자가 실제 홈 화면 목업 스크린샷을 공유 — 아래 두 지점을 재확인하고 반영했다.

- **날씨**: 애초 "API 호출 없이 준비 중 placeholder"로 정했으나, 목업엔 시간대별 강수확률(지금/1~4시간
  후)·아이콘·우산 추천 배너가 있는 상세 위젯이었다. 사용자 확인 결과 **Mock 데이터로 상세 위젯을 구현**하기로
  변경(단, 실제 외부 공급자 호출은 여전히 안 함 — `WEATHER-001`(§5.12) 응답 형태 그대로 `weatherApi.ts` Mock
  추가, `provider`는 문서 그대로 `"UNDECIDED"` 고정). `DEC-SF-003`(공급자·호출 경계) 자체는 여전히 미확정 상태
  유지 — 이번에 확정된 건 "UI를 어떻게 보여줄지"뿐, "누구에게 실제로 물어볼지"가 아니다.
- **중앙 "현재 상태·지도" 영역**: 목업엔 완전히 빈 흰 박스로 표시됨. 기존에 만들어둔 "현재 대여 요약 카드 +
  지도에서 보기 버튼"은 이 영역에서 빼고, 사용자 확인대로 **당장은 빈 박스만** 둔다. 대여 요약을 어디에 다시
  배치할지는 이 영역 설계가 확정되면 재논의.
- 헤더·인사말·챗봇 버튼 스타일도 목업 그대로 맞춤(로고+학교명+알림 아이콘 배지 점, "안녕하세요 OOO님" +
  큰 타이틀, "챗봇" 텍스트 pill 버튼).
