> 결정 사항(2026-07-31): 토큰 저장은 Zustand 메모리에만(영속 저장 없음). "비밀번호를 잊으셨나요?" 링크는

## 1. 구현 목표

- 로그인 화면(`SCR-APP-AUTH-001`)을 와이어프레임 레이아웃대로 구현한다.
- `AUTH-001`(로그인)/`AUTH-002`(로그아웃)를 **Mock API**로 연동한다 — 실제 Spring 서버 없음, Kiosk와 동일하게 Mock 우선 원칙.
- 로그인 성공 여부에 따라 **로그인 화면 ↔ 하단 탭(Phase 1에서 만든 것)**을 전환하는 최소한의 인증 게이트를 만든다.
- 로그아웃은 아직 만들지 않은 마이페이지 화면 대신, 임시로 마이페이지 자리표시자에 로그아웃 버튼 하나만 둬서 왕복 테스트가 되게 한다(마이페이지 실제 UI는 후속 Phase).

## 3. 각 요소의 역할과 결정 사항

### `authApi.ts` (Mock)
Kiosk의 `stationApi.ts`/`rentalApi.ts`와 같은 패턴 — `setTimeout`으로 지연 후 고정 시나리오 값을 반환한다.

```ts
// 수동 테스트 시나리오 — MOCK_SCENARIO를 바꿔서 성공/실패 화면을 확인한다.
const MOCK_SCENARIO: 'SUCCESS' | 'INVALID_CREDENTIALS' = 'SUCCESS'

export function login(request: LoginRequest): Promise<LoginResponse>
export function logout(): Promise<{ loggedOut: true }>
```

PROJECT_GUIDE.md §5.1 응답 형태(`accessToken`, `tokenType`, `expiresAt`, `user{userId,displayName,schoolName,faceRegistered}`) 그대로 따른다.

### `useAuthStore` (Zustand)
```ts
interface AuthState {
  accessToken: string | null
  user: AuthUser | null
  login: (request: LoginRequest) => Promise<'SUCCESS' | 'INVALID_CREDENTIALS'>
  logout: () => Promise<void>
}
```
- 토큰은 메모리에만 존재 — 앱을 껐다 켜면 다시 로그인해야 한다(이번 결정에 따른 자연스러운 동작, 버그 아님).
- 비밀번호 자체는 이 스토어에 저장하지 않는다(PROJECT_GUIDE.md §9.3 "제출 직후 화면 상태에서 제거" 원칙 — `LoginScreen`의 로컬 입력 상태에서만 잠깐 존재하고, 성공/실패 응답 후 즉시 버림).

### `LoginScreen`
와이어프레임 1~2번 페이지 그대로:
- 로고 "빌리산" + "싸피대학교" 서브타이틀
- "이메일" 라벨 + `TextField`(placeholder "이메일을 입력해주세요")
- "비밀번호" 라벨 + `TextField`(placeholder "비밀번호를 입력해주세요", `secureTextEntry`)
- 실패 시(`INVALID_CREDENTIALS`): 두 입력창 테두리를 `error-bg` 톤으로, 입력창 바로 아래 "계정 정보를 확인해주세요"(`error-text` 색) 표시 — 와이어프레임 2번 페이지 그대로
- "로그인" 버튼(`Button`, `primary` 배경)
- **"비밀번호를 잊으셨나요?" 링크는 넣지 않는다**(위 결정 사항)

### `RootNavigator` / `TabNavigator` 분리
- `RootNavigator`: `useAuthStore`의 `accessToken` 유무로 `LoginScreen` vs `TabNavigator` 중 하나만 렌더링(둘 다 마운트하지 않음 — 로그인 전 상태에서 탭 화면 API 호출이 일어나지 않게).
- `TabNavigator`: Phase 1에서 만든 하단 탭 4개(홈/지도/내역조회/마이페이지) 그대로, 파일만 분리.

### 마이페이지 임시 로그아웃 버튼
마이페이지 실제 화면(사용자 정보, 대여 현황 카드 등)은 이번 Phase 범위가 아니다. 다만 로그아웃(`AUTH-002`)까지 이번 Phase 목표라, 자리표시자 문구 아래에 `Button` 하나만 임시로 추가해 `useAuthStore().logout()`을 호출하게 한다. 마이페이지를 실제로 만들 Phase에서 이 버튼은 정식 위치(와이어프레임 5번 페이지의 "로그아웃" 목록 항목)로 옮겨진다.

## 4. 테스트 방법 (수동 확인 기준)

1. 앱 실행 시 로그인 화면이 먼저 보이는지 확인(탭이 안 보여야 함)
2. 아무 이메일/비밀번호나 입력 후 로그인 → `MOCK_SCENARIO='SUCCESS'` 상태에서 하단 탭 화면으로 전환되는지 확인
3. `authApi.ts`의 `MOCK_SCENARIO`를 `'INVALID_CREDENTIALS'`로 바꾸고 재시도 → 입력창이 에러 톤으로 바뀌고 "계정 정보를 확인해주세요" 문구가 뜨는지, 탭으로는 안 넘어가는지 확인
4. 로그인 성공 후 마이페이지 탭 → 임시 로그아웃 버튼 클릭 → 다시 로그인 화면으로 돌아가는지 확인
5. `npx tsc --noEmit` 통과 확인

## 5. 예상 리스크

1. **비밀번호 로컬 상태 처리** — `LoginScreen`의 `TextField` value는 React state로 잠깐 들고 있어야 입력이 되므로, 요청 전송 직후(성공이든 실패든) 반드시 지운다. 빠뜨리면 PROJECT_GUIDE.md §9.3 위반.
2. **토큰 메모리 저장의 한계** — 이번 결정(Zustand 메모리만)은 앱 재시작 시 로그아웃되는 게 "정상 동작"이 된다. 나중에 실제 서버 연동 단계에서 영속 저장이 필요해지면 별도 승인 받고 `expo-secure-store` 등을 추가해야 한다(지금은 설치하지 않음).
3. **마이페이지 임시 버튼 위치** — 정식 마이페이지 화면을 나중에 만들 때 이 임시 버튼을 정리하는 걸 잊지 않아야 한다(§3에 기록해둠).

## 6. 이번 Phase에서 하지 않을 일

- 마이페이지 실제 화면(사용자 정보 카드, 대여 현황 등) — 로그아웃 버튼 하나만 임시로 추가
- 홈/지도/내역조회 화면의 실제 내용
- 토큰 영속 저장(`expo-secure-store` 등) — 이번엔 메모리 전용
- 실제 Spring 서버 연동(계속 Mock)
- "비밀번호를 잊으셨나요?" 기능
