## 3. 배포 시 특이사항

### 3.1 CI/CD 구성

`.gitlab-ci.yml` 은 `backend/ci.yml` **하나만** include합니다. `frontend/ci.yml` · `iot/ci.yml` · `ai/ci.yml`
은 주석 처리 상태입니다 — **백엔드만 자동 배포되고 나머지는 수동입니다.**

```
stages: build → test → deploy

backend-build    backend/** 변경 시
backend-test     backend/** 변경 시. MySQL 컨테이너를 띄워 통합 테스트
backend-deploy   develop 브랜치 + backend/** 변경 시에만
```

**배포 잡이 하는 일**

```bash
docker build -t billisan-app:latest .
cp docker-compose.yml mosquitto.conf ~/billisan/
cd ~/billisan && docker compose up -d db app mosquitto
```

### 3.2 ⚠ `develop` 브랜치가 protected 여야 합니다

`backend-deploy` 는 `docker compose up -d` 만 실행합니다. `docker-compose.yml` 의
`${GMS_KEY}` · `${KMA_API_KEY}` · `${JWT_SECRET}` · `${MYSQL_*}` 는 **잡 환경변수에서 채워집니다.**

GitLab의 **Protected 변수는 protected 브랜치에서만 주입**되므로, `develop` 이 protected 로
설정돼 있지 않으면 **빈 값으로 컨테이너가 뜹니다.**

### 3.3 ⚠ 관리자 Web은 Vercel rewrite 프록시로 백엔드에 붙습니다

배포본은 HTTPS(Vercel)인데 백엔드는 **평문 HTTP(8080)** 입니다. 브라우저가 혼합 콘텐츠로
차단하므로 `VITE_API_BASE_URL` 에 절대 URL을 넣는 방법은 동작하지 않습니다.

```json
// frontend/web/vercel.json
{ "source": "/api/(.*)", "destination": "http://i15a201.p.ssafy.io:8080/api/$1" }
```

**CORS는 이 프록시로 해결되지 않습니다.** 브라우저가 POST·PATCH에 `Origin` 을 붙이고 Vercel이
그대로 전달하므로, Spring `CorsFilter` 허용 목록에 배포 도메인이 없으면 403입니다.

**배포 도메인이 바뀌면 rewrite 목적지와 CORS 허용 목록을 둘 다 고쳐야 합니다.**

> Vercel 미리보기 URL은 배포마다 도메인이 달라 허용 목록에 넣을 수 없고, Deployment Protection이
> `/api/*` 까지 막습니다. 검증은 고정 주소(`web-sigma-two-20.vercel.app`)로 하세요.

### 3.4 ⚠ Jetson Orin — 저장소만으로는 기동되지 않습니다

`iot/orin/orin_service.py` 가 임포트하는 다음 2개가 저장소에 없습니다 (실기 경로에만 존재).

- `umbrella_inspector_onnx.py`
- `yolov8n.onnx`

모듈 최상단 임포트라 `try/except` 방어가 무력하고, `ModuleNotFoundError` 로 프로세스가 즉사합니다.
**파손 검증만이 아니라 얼굴 인증·대여·반납이 전부 멈춥니다.**

**획득 경로 — 저장소에 없으므로 별도로 수령해야 합니다.**

| 파일 | 소재 | 조치 |
|---|---|---|
| `umbrella_inspector_onnx.py` | Orin 실기 `/home/a201/AIoT/damage_check_v1/` | **저장소 커밋 필요** |
| `yolov8n.onnx` | 동일 | **저장소 커밋 필요** |

> 저장소의 `ai/anomaly_detection/jetson_deploy/damage_check_v1/` 에 있는 `infer.py`(클래스
> `UmbrellaInspector`, `.pt` + ultralytics + torch)는 **대체재가 아닙니다.** Orin 런타임이 쓰는
> `UmbrellaInspectorOnnx` 는 생성자 인자(`detector_onnx_path`)와 탐지기 형식(ONNX)이 다릅니다.

**`DAMAGE_CHECK_DIR` 에는 아래가 모두 있어야 합니다** — 위 2개만 넣으면
`No module named 'crop'` 으로 같은 지점에서 다시 죽습니다.

| 파일 | 출처 |
|---|---|
| `metadata.json` · `weights/onnx/model.onnx` | 저장소 |
| `crop.py` · `decision.py` | 저장소 — `infer.py` 및 검증기가 최상단 모듈로 임포트 |
| `umbrella_inspector_onnx.py` · `yolov8n.onnx` | **저장소 미포함, 별도 수령** |

`inspection.py` 가 `sys.path.insert(0, DAMAGE_CHECK_DIR)` 로 이 디렉터리를 모듈 검색 경로에
넣으므로, `crop` · `decision` 도 같은 폴더에서 찾습니다. **저장소 폴더를 통째로 복사한 뒤
수령분 2개를 추가하는 순서**가 안전합니다 (`damage_check_v1/README.md` 도 폴더 통째 복사를 안내).

### 3.5 ⚠ Jetson 패키지는 일반 PyPI로 설치하면 안 됩니다

`torch` · `onnxruntime-gpu` 는 PyPI에 aarch64 공식 빌드가 없습니다.

```bash
python -m pip install torch==2.11.0 torchvision==0.26.0 \
  --index-url=https://pypi.jetson-ai-lab.io/jp6/cu126
python -m pip install onnxruntime-gpu==1.24.0 \
  --index-url=https://pypi.jetson-ai-lab.io/jp6/cu126
```

- `.dev` 가 아니라 **`.io`** 도메인입니다
- `iot/orin/requirements.txt` 의 `onnxruntime-gpu @ file:///home/a201/AIoT/...` 로컬 whl 경로는
  다른 머신에서 설치가 실패합니다. 위 절차로 대체하세요
- 일반 `onnxruntime`(CPU)로 대체하면 provider 폴백이 **설계대로** 동작해 **에러 없이 CPU로 떨어집니다**

### 3.6 ⚠ TensorRT 엔진 캐시 워밍업

DINOv2 ViT 엔진 빌드가 캐시 없이 **384초**, 캐시 사용 시 **9초**입니다 (`infer.py` 실측 주석).
캐시 디렉터리(`.trt_cache`)는 코드가 자동 생성하므로 **시연 전 1회 실행**해 두세요.

### 3.7 ⚠ GPU 메모리

`orin_service.py` 가 `buffalo_l` CUDA 세션에 아레나 상한을 겁니다 (세션당 2GB,
`arena_extend_strategy=kSameAsRequested`). 이게 없으면 뒤에 로드되는 우산 검증 TensorRT 엔진이
**OOM(NvMap error 12)** 으로 죽습니다.

### 3.8 기타

- **CI 아티팩트 없음** — `backend-build` 는 컴파일 fail-fast 검증용입니다. jar 업로드를 하면
  GitLab 한도를 넘어 `413` 으로 파이프라인 전체가 실패한 이력이 있습니다
- **CI 컨테이너 TZ 미설정** — `ci.yml` 의 `docker run` 이 TZ를 지정하지 않아 UTC로 돌아갑니다.
  `build.gradle` 의 `jvmArgs` 로 보정되고 있습니다
- **Kiosk 폰트가 jsDelivr CDN 런타임 의존** — 현장 인터넷이 끊기면 시스템 폰트로 대체됩니다
  (`font-display: swap`). 관리자 Web은 `pretendard` npm 패키지로 번들에 포함돼 있습니다
- **`model.onnx` 134MB가 Git LFS 없이 커밋**되어 있습니다. clone 용량에 반영됩니다

## 5. 클론 후 실행 순서

### 5.1 백엔드 (로컬)

```bash
git clone https://lab.ssafy.com/s15-webmobile3-sub1/S15P11A201.git
cd S15P11A201/backend

cp .env.example .env          # 값 채우기 (JWT_SECRET은 32바이트 이상)
docker compose -f local/docker-compose.yml up -d
./gradlew bootRun             # Flyway가 V1~V20을 자동 적용
```

> ⚠ **반드시 `local/docker-compose.yml` 을 쓰세요.** 루트의 `backend/docker-compose.yml` 은
> **배포 전용**이라 `db` 서비스에 포트 매핑이 없습니다 (컨테이너 네트워크 `billisan-net` 내부에서만
> 접근 가능). `.env.example` 의 `SPRING_DATASOURCE_URL` 은 호스트 `localhost:3306` 을 보므로,
> 배포용 compose로 띄우면 **`bootRun` 이 DB 연결에 실패합니다.**

| | `backend/docker-compose.yml` (배포) | `backend/local/docker-compose.yml` (로컬) |
|---|---|---|
| `db` 포트 | 없음 | `3306:3306` |
| 컨테이너명 | `billisan-db` / `billisan-mqtt` | `billisan-db-local` / `billisan-mqtt-local` |
| 볼륨 | `db-data` | `db-data-local` |
| mosquitto.conf | `backend/mosquitto.conf` | `backend/local/mosquitto.conf` |
| 타임존 | `TZ=Asia/Seoul` + `--default-time-zone=+09:00` | **미설정** (JDBC `serverTimezone` 으로만 보정) |

- Swagger UI — `http://localhost:8080/swagger-ui/index.html`
  (`application.yaml` 에 springdoc 커스텀 경로 설정이 없어 이 경로가 정식입니다.
  `/swagger-ui.html` 도 리다이렉트로 동작은 합니다)
