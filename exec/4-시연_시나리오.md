# 4. 시연 시나리오

> 대상: Billisan (빌리산) Kiosk
> 흐름: ① 얼굴 인증 → 우산 대여 ② 얼굴 인증 → AI 보조 검수(NORMAL) → 반납
> 조작: **발표자**가 Kiosk 화면 조작 / **시연자**가 카메라·우산 물리 동선

---

## 4.1 시연 구성

| 항목 | 내용 |
|---|---|
| 시연 장비 | Kiosk 화면 1대 · 카메라(Jetson Orin Nano) · 물리 SLOT 1개 |
| 발표자 | Kiosk 화면 조작 + 나레이션. 카메라 화각 밖에서 조작 |
| 시연자 | 카메라 정면 위치, 우산 반출·투입. **화면 조작 없음** |
| 총 소요 | 대여 약 60초 + 반납 약 90초 |
| 총 클릭 | **4회** (대여 진입 1 · 홈 복귀 1 · 반납 진입 1 · 홈 복귀 1) |

> 발표자의 화면 조작은 시연 진행용 트리거이며, 실제 사용자 동선은 시연자의 물리 행동입니다. 시연 시작 시 이 점을 1문장으로 선언합니다.

---

## 4.2 흐름 A — 얼굴 인증 → 우산 대여

### A-1. 홈 / 대기 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 상단: 서비스 로고 · 대여소명 / 중앙: `[대여하기]`(좌) `[반납하기]`(우) 2개 버튼 / 하단: 잔여 SLOT 수 |
| **발표자 클릭** | **화면 중앙 좌측 `[대여하기]`** |
| 시연자 | 대기 (카메라 화각 밖) |
| 전이 조건 | 클릭 즉시 |

### A-2. 얼굴 인증 안내 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: 카메라 프리뷰 영역 / 상단: "카메라를 바라봐 주세요" 안내 / 하단: `[취소]` |
| **발표자 클릭** | **없음** (자동 전환) |
| 시연자 | **카메라 정면으로 이동**, 40~60cm 거리에서 정지 |
| 전이 조건 | 프리뷰에 얼굴 검출 |

### A-3. 인증 진행 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: 프리뷰 + 진행 인디케이터 / **사용자 이름·학번·UUID 미표시** |
| **발표자 클릭** | **없음** |
| 시연자 | 2~3초 정지 유지 |
| 내부 동작 | Orin 온디바이스 얼굴 임베딩 → pgvector `FACE_PROFILE` 유사도 조회. 원본은 Orin 밖으로 나가지 않고, Vector Commit·실패·Timeout 직후 즉시 삭제 |
| **나레이션** | "얼굴 원본은 이 장치 안에서만 처리되고 즉시 삭제됩니다. 서버로 전송되지 않습니다." |

### A-4. 인증 결과 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: "인증되었습니다" / **식별자 일절 미표시** |
| **발표자 클릭** | **없음** |
| 시연자 | 정지 유지 |
| 내부 동작 | Pi → Spring(MQTT)으로 대여 자격 검증. Kiosk에는 `userRef`·UUID·이름·학번을 반환하지 않음 |
| **나레이션** | "화면에 이름도 학번도 없습니다. 키오스크는 누구인지 모른 채 '대여 가능' 여부만 받습니다." |

### A-5. SLOT 개방 안내 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: 열린 SLOT 위치 안내 그래픽 / 하단: "우산을 꺼내주세요" |
| **발표자 클릭** | **없음** |
| 시연자 | 대기 |
| 내부 동작 | Spring 승인 → MQTT → Pi → **MG90S 서보 개방** |

### A-6. 반출 확인 대기 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: 대기 인디케이터 / 하단: "우산을 꺼내면 자동으로 진행됩니다" |
| **발표자 클릭** | **없음** |
| 시연자 | **SLOT에서 우산을 꺼냄** |
| 내부 동작 | **DRV5032 홀센서** 상태 변화 감지 → Pi가 Spring에 보고 |
| **나레이션** | "센서가 실제 반출을 확인합니다. 클릭만으로 완료 처리하지 않습니다." |

### A-7. 대여 완료 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: "대여 완료" / 반납 기한 안내 / 하단: `[처음으로]` |
| **발표자 클릭** | **없음** (표시만) |
| 시연자 | 우산을 든 상태로 정지 |
| 내부 동작 | Spring `RENTAL` 생성 → Result 수신 후에만 완료 표시 |
| **나레이션** | "무료 24시간입니다. 이후 하루 1,000원 연체료가 붙습니다." |

### A-8. 홈 복귀

| 구분 | 내용 |
|---|---|
| **발표자 클릭** | **화면 하단 중앙 `[처음으로]`** |
| 시연자 | 퇴장 |

---

## 4.3 흐름 B — 얼굴 인증 → AI 보조 검수 → 반납

### B-1. 홈 / 대기 화면

| 구분 | 내용 |
|---|---|
| **발표자 클릭** | **화면 중앙 우측 `[반납하기]`** |
| 시연자 | 우산을 들고 재입장 |
| **나레이션** | "같은 사람이 반납합니다." |

### B-2. 얼굴 인증 안내 → 진행 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | A-2 · A-3과 동일 |
| **발표자 클릭** | **없음** |
| 시연자 | 카메라 정면 정지 2~3초 |
| **나레이션** | "인증 방식은 대여와 완전히 동일합니다." |

### B-3. 인증 결과 · 반납 대상 확정 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: "반납할 대여 건이 확인되었습니다" / 식별자 미표시 |
| **발표자 클릭** | **없음** |
| 내부 동작 | Spring이 진행 중 `RENTAL` 조회 → 반납 대상 확정 |

### B-4. SLOT 개방 · 투입 안내 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: 열린 SLOT 안내 / 하단: "우산을 넣어주세요" |
| **발표자 클릭** | **없음** |
| 내부 동작 | 서보 개방 |

### B-5. 투입 확인 화면

| 구분 | 내용 |
|---|---|
| **발표자 클릭** | **없음** |
| 시연자 | **우산을 SLOT에 투입** 후 카메라 시야에서 비켜섬 |
| 내부 동작 | 홀센서 변화 감지 → Pi가 Orin에 검수 Command 전달 |

### B-6. AI 보조 검수 진행 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: 검수 진행 애니메이션 (**로컬 capped 0~90%**) / 하단: "검수 중입니다" |
| **발표자 클릭** | **없음** |
| 내부 동작 | Orin 온디바이스 **YOLOv8n** 우산 검출 → **PatchCore** 이상(파손·오염) 탐지 |
| **나레이션** | "여기가 AI 핵심입니다. 파손 형태가 매번 다르기 때문에 규칙 기반 판별이 불가능합니다." |
| 참고 | 진행바가 90%에서 멈추는 것은 설계입니다. Result 수신 전 100%·완료 표시를 금지했습니다. |

### B-7. 검수 결과 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: 결과 `NORMAL` 표시 / 진행바 100% |
| **발표자 클릭** | **없음** |
| 내부 동작 | Orin Result 수신 후에만 100% 도달 |
| **나레이션** | "**AI 결과는 보조 판단입니다.** 공식 파손 확정과 과금은 관리자가 실물을 보고 최종 품질 판정을 내린 뒤에만 생성됩니다." |

### B-8. 반납 완료 화면

| 구분 | 내용 |
|---|---|
| 화면 구성 | 중앙: "반납 완료" / 하단: `[처음으로]` |
| **발표자 클릭** | **없음** (표시만) |
| 내부 동작 | Spring `RETURN_ATTEMPT` 확정 → SLOT 재고 복귀 |
| **나레이션** | "반납 완료. 슬롯 재고가 다시 1이 됩니다." |

### B-9. 홈 복귀

| 구분 | 내용 |
|---|---|
| **발표자 클릭** | **화면 하단 중앙 `[처음으로]`** |
| 시연자 | 퇴장 |

---

## 4.4 발표자 조작 요약

```
① 홈 화면 중앙 좌측  [대여하기]
   → A-2 ~ A-7 무조작 (6단계)
② 화면 하단 중앙     [처음으로]
③ 홈 화면 중앙 우측  [반납하기]
   → B-2 ~ B-8 무조작 (7단계)
④ 화면 하단 중앙     [처음으로]
```

**총 클릭 4회.** 그 외 구간은 화면을 만지지 않습니다. 무조작 구간이 긴 것은 센서와 AI가 흐름을 진행시키기 때문입니다.

---

## 4.5 화면별 강조 포인트

| 화면 | 강조 내용 |
|---|---|
| A-3 | 얼굴 원본 온디바이스 처리·즉시 삭제 (개인정보 방어 논리) |
| A-4 | 화면에 식별자가 없다는 사실 — 손으로 화면을 가리키며 설명 |
| A-6 | 완료는 클릭이 아니라 센서가 결정 |
| B-6 | 규칙 기반 판별 불가 → AI 필요성 |
| B-7 | AI는 보조, 확정은 관리자 최종 품질 판정 |

> 화면명·버튼 라벨은 `frontend/kiosk/docs/09-screen-flow.md` 실제 값으로 교체 후 확정합니다. 위치 표기(중앙 좌측/우측, 하단 중앙)와 클릭 순서는 그대로 유효합니다.
